# OpenCode Sessions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** OpenCode 2.x sessions in the hall beside Claude Code's: status, task, context, subagents, Chronicon and
Tithe, and permission prompts answered from the card, the toast and the remote view.

**Architecture:** A new module `src-tauri/src/opencode/` reads OpenCode's SQLite DB read-only (`db.rs`) and talks
to its loopback service only for live state and replies (`service.rs`); `mod.rs` builds `Session`s that the poll
loop appends to the Claude roster. The Chronicon gets a second feeder fed from `session_message` rows. The UI only
learns a `source` field and a second answer target.

**Tech Stack:** Rust (Tauri 2, `rusqlite` bundled — new, accepted, `sysinfo`, `serde_json`, `std::net`), plain ES
modules, node `assert` tests.

Spec: `docs/superpowers/specs/2026-10-16-opencode-design.md`.

## Global Constraints

- OpenCode 2.x only: no `session_v2` table, or a registration `version` below 2 → the source returns nothing, no
  error toast, one `eprintln!` per app run.
- Read-only on OpenCode: DB opened `SQLITE_OPEN_READ_ONLY | SQLITE_OPEN_NO_MUTEX`, `busy_timeout(200 ms)`, never
  `immutable`; one transaction per tick, dropped before the tick ends. Never write, rename or delete anything under
  OpenCode's data, state or config dirs.
- HTTP only to a registration `url` whose host is `127.0.0.1`, `localhost` or `[::1]`; anything else → no service.
  Basic auth user `opencode`. Connect and read timeouts 300 ms.
- The service password never enters `Session`, an event, a log line, an error string or a test snapshot. Errors
  name the route, never the header.
- Ids that go into a URL path pass `valid_opencode_id` (`ses_`/`per_`/`msg_` prefix + `[A-Za-z0-9]{1,64}`).
- Idle window `OPENCODE_IDLE_MS = 900_000` (15 min): a constant, not a setting.
- Work in a worktree branch `opencode`. Commit only with a pathspec; never push. The controller (not the
  implementer) merges, pushes, rebuilds and silent-installs the NSIS build after each reviewed task.
- Windows: `PYTHONUTF8=1` for any Python.
- Tests: `cargo fmt --manifest-path src-tauri/Cargo.toml --check` (CI's `fmt` job), `cargo test --manifest-path src-tauri/Cargo.toml` and `for t in ui/*.test.mjs; do node "$t" || echo "FAIL $t"; done`.
- Docs move in the same task as the behaviour they describe.

- [ ] **Step 1:** Copy the `CREATE TABLE` / `CREATE INDEX` statements of `session_v2` and `session_message` from

- [ ] **Step 2: Failing tests** in `db.rs` on an in-memory DB built from `schema.sql` plus inserted rows:

### Task 2: Registration file and loopback client

**Files:**
- Create: `src-tauri/src/opencode/service.rs`
- Modify: `src-tauri/src/registry/prompt.rs` (`valid_opencode_id` + tests), `src-tauri/src/registry/mod.rs` (export)

- [ ] **Step 1: Failing tests:**
  - `registration(text)` parses `{id, version, url, pid, password}`; rejects version < 2, a non-loopback host
    (`http://10.0.0.5:4096`, `http://evil.example`), a non-http scheme, a missing field.
  - `Debug` of the registration does not print the password (manual `Debug` impl).
  - A test `TcpListener` serving canned responses: `active()` parses `{data:{ses_x:{type:"running"}}}`;
    `pending(id)` parses a `Permission.Request[]`; `reply(sid, rid, "once")` sends
    `POST /api/session/{sid}/permission/{rid}/reply` with body `{"decision":"once"}` and an
    `Authorization: Basic` header for `opencode:<password>`; a 401 or a timeout returns `Err` whose text holds
    neither the password nor the header.
  - `valid_opencode_id`: accepts `ses_01abcXYZ`, `per_9`; rejects `ses_`, `ses_a/b`, `ses_a?x`, `../`, 65+ chars.
- [ ] **Step 2:** Implement: state dir per the spec (`XDG_STATE_HOME` non-empty, else `~/.local/state`, then
  `/opencode/service.json`); a hand-written base64 encoder (a dozen lines, tested against RFC 4648 vectors) rather
  than a crate; HTTP/1.1 with `Connection: close`, `Content-Length` body read.
- [ ] **Step 3:** Tests green; commit `opencode: registration and loopback client`.

### Task 3: Roster source

**Files:**
- Modify: `src-tauri/src/opencode/mod.rs`, `src-tauri/src/registry/mod.rs` (`Session.source`,
  `Session.opencode_request`), `src-tauri/src/registry/sessions.rs` (set `source: "claude"`), `src-tauri/src/demo.rs`
  (one demo session with `source: "opencode"`), `src-tauri/src/main.rs` (append to the roster)

- [ ] **Step 1: Failing tests** for a pure `build(rows, service: Option<Live>, now_ms) -> Vec<Session>` where
  `Live` = (pid alive, active ids, pending per id):
  - running + pid alive → `busy`; running + dead service → `idle`; pending permission → `waiting`, `waiting_for`
    "permission", `asks` = `action` + first resource, `opencode_request` = `per_…`;
  - `dept` / `temp` from `directory` via `dept_of` / `temp_dept`; `title` from the session title; `task` from the
    last user text; `context` from the last assistant; children with `parent_id` become `helpers` of their parent
    and are not top-level sessions;
  - the password appears nowhere in `serde_json::to_string(&roster)`.
- [ ] **Step 2:** `Source` keeps the connection path, a (len, mtime) memo of `opencode.db` + `-wal`, and asks the
  service (active, then pending for running ids only) only while a session is running. `poll_loop` appends
  `source.roster(now)` to `poller.roster(...)` outside demo mode; `registry::merge` / `track_compaction` run on the
  combined list (check `merge` keys on `id`, not `pid`).
- [ ] **Step 3:** Run the app in demo mode, check the OpenCode demo scribe shows. Tests green; commit
  `opencode: sessions in the roster`.
