# Rank Art Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each rank (high, standard, novice) gets its own drawing and its own colour, for scribes and adepts, in Flat and 39°, so the rank reads at a glance from behind.

**Architecture:** Optional rank-prefixed frames (`high up 0`, `novice N 1`) in the existing `scribe`, `adept`, `scribe39`, `adept39` sheets. `ui/sprites.js` builds a per-rank layer from them, only where the rank frame comes from the same source as the plain frame; `ui/actors.js` picks the rank frame, else the plain one. Checks, catalogue, docs follow; then the 40k art (base sheets, shared by Ordos A–E) and the colours.

**Tech Stack:** plain ES modules, Node test scripts (`node ui/<name>.test.mjs`, `node:assert`), PNG art sheets in the key palette `ui/art/key.gpl`, Tauri app.

**Spec:** `docs/superpowers/specs/2026-11-21-rank-art-design.md`

## Global Constraints

- Ranks are exactly `RANKS = ['high', 'standard', 'novice']` (`ui/sprites.js`); `rankOf` is unchanged.
- Rank frame name: `<rank> <frame>`, `<frame>` a frame the family knows (walk frames, gestures, `arm`, `armL`, `scroll`, glyphs are **not** rank-drawn: arms, scroll and glyphs stay shared).
- A rank frame is used only when it comes from the same source (theme folder, `artOf` folder or base) as the plain frame it replaces.
- A rank frame has the size of its plain frame.
- Per-rank anchors: `meta.anchors.<rank>` = an object of base anchor keys only, laid over the base anchors for that rank.
- Rank frames are optional; a 39° sheet's completeness (`REQ39`) never requires them.
- The department sash `y` stays on every rank body; high's gilt never uses `y`.
- Standard keeps today's frames and colours.
- Views: Flat 3/4 and 39° only.
- Every non-40k theme renders exactly as before.
- After each task that ends a stage: `node ui/art.test.mjs && node ui/sprites.test.mjs`, then the whole suite (`for t in ui/*.test.mjs; do node "$t"; done`), then rebuild and silently reinstall the NSIS build (project memory "reinstall after each step").

## Review Focus

1. A theme with its own scribe (Darwin, Cyber...) but no rank frames: must show its own frames at every rank, never the base 40k rank frames (Task 1 test `same source`).
2. A walking left scribe at high rank: the rank's `right` frames mirrored, not the plain ones (Task 1 test `left mirrors rank right`).
3. A pack that ships `high up 0` at the wrong size, or `royal up 0`: refused / ignored with a warning, the app keeps running (Task 3 tests).
4. A pack sheet with `meta.anchors.high.feet` but no `high` frames: loads, the anchor is harmless (Task 3 test `rank anchors alone`).
5. An adept at high rank with a kind glyph: the glyph sits on the rank body at the rank's glyph anchor (Task 2 test `glyph on rank body`).

### Task 1: Rank layer in `ui/sprites.js`

**Files:**
- Modify: `ui/sprites.js` (`anchorsOf`, `useArt`, the `BUILD39` scribe39/adept39 entries, the exports' comments)
- Create: `ui/rankart.test.mjs`

**Interfaces:**
- Produces: `export function rankLayer(family, frames, same)` → `{ [rank]: { [dir]: rows[] , gesture?: { [g]: rows } } }`; `family` one of `scribe | adept | scribe39 | adept39`; `frames` the merged sheet frames; `same(name)` → true when `name` and its plain frame share a source. Flat families give `up down right left` (left = right mirrored, per frame, falling back per frame to the plain frame); 39° families give `E W S N`. A rank with no frame of its own is absent. `standard` is never built unless drawn.
- Produces: `export function rankAnchors(sheet)` → `{ [rank]: anchors }` in logical px, each the base anchors with the rank's object laid over; `anchorsOf` ignores the `RANKS` keys.
- Produces: `SCRIBE.rank`, `ADEPT.rank`, `SCRIBE39.rank`, `ADEPT39.rank` (from `rankLayer`), `SCRIBE_AT.rank`, `ADEPT_AT.rank`, `SCRIBE39_AT.rank`, `ADEPT39_AT.rank` (from `rankAnchors`), refilled per theme.

- [ ] **Step 1: Write the failing tests in `ui/rankart.test.mjs`** with fabricated sheets (rows of one char per frame, so identity is checkable):
