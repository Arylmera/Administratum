# L1c: the pure core of I6 (CI verdict)

Spec: `docs/superpowers/specs/2026-11-21-ci-verdict-design.md` (amended: no toast, a lamp per folder, a start check
per folder). Joint spec: `2026-11-21-parallel-waves-design.md`, lane L1c, decisions D1 and D7.
This lane is the backend core only: no thread, no UI, no toast. Lane L2b wires it.

## Items

1. `src-tauri/src/ci.rs` (new), pure and testable:
   - push output parsing (`To <url>`, ref update lines, new branch, forced, up-to-date / quiet = none);
   - GitHub remote URL parsing (`owner/repo`, anything else = none);
   - ref lookup (loose ref then `packed-refs`, worktrees through `git::worktree_repo` / `git::head_file`),
     checked against the short SHA; the start check's inputs (branch from HEAD, its remote ref, the repo);
   - the verdict over check-runs and statuses (fail early, pass after two stable polls, running done/total);
   - the watch state machine with an injected clock (`Watcher`), a `Gh` trait for the runner, the real runner
     (`RealGh`, `gh api repos/<owner>/<repo>/...`, arguments direct, `no_window`, candidate paths).
2. `chronicle/mod.rs`: `CiPush` side record for a live push, collected on the cursor, drained by `Chronicle::take_ci`.
   `Src` gains `cwd` and `live`.
3. `monitor.rs`: `Config.ci` from `adm.ci`, default off. No toast field.
4. `registry/mod.rs`: `Session.ci: Option<CiState>` (additive, camelCase), `CiStatus`.
5. `main.rs`: the one line `mod ci;`.
6. `docs/DEVELOPMENT.md`: a `ci.rs` row and the changed rows.

## Tests

The I6 spec's "Tests" section, the pure parts: recorded `gh api` JSON for each verdict case, push output parsing,
ref lookup (loose, packed, worktree), the watch state machine with a fake clock and a recording stub runner, the off
switch (no call at all), the start check cases; plus `CiPush` collection (live only), `Config.ci`, and the
`Session.ci` JSON shape.
