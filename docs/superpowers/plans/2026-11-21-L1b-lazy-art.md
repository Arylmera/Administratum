# L1b: lazy theme art (F1)

**Goal:** the app starts with the base art and the active theme's art only; another theme's art loads when it is
needed. Today `ui/sprites.js` and `ui/faces.js` load every theme's sheets at import (about 445 requests).

## Design

- `sprites.js`: the per-theme loader becomes `loadTheme(theme)` (memoised, same checks and pack handling as before).
  New exports: `loadArt(id)` (the theme's own art and the folder it borrows, `artOf`, then the hooks below),
  `loadAllArt()` (every registered theme: the tools, the gallery, the tests that visit every world),
  `switchTheme(id)` (`loadArt`, then `setTheme`; the old theme stays until the art is ready; the last call wins),
  `onLoadArt(fn)` (faces.js registers its own loader).
- At import: base art, the active theme, and every pack theme (a pack is checked at start, so Settings still lists
  its problems and a broken theme is still left out before the user can pick it). The family names of every theme
  are still checked at import (no I/O).
- `faces.js`: same split (`loadFaces(id)`), registered with `onLoadArt`.
- Callers: `app.js` and `settings.js` switch with `switchTheme`; the art tools, `tools/sprites.html` and the tests
  that visit every world call `loadAllArt()` first.

## Tests

- `ui/lazyart.test.mjs` (new): a counting `fetch` stub (the page's loading path); importing with `cyber` active asks
  for the base sheets and cyber's only; a pending switch to `vault` keeps `cyber`, then asks for vault's only; a switch
  back asks for nothing; `loadAllArt()` loads the rest. Fails on the base commit (every theme is asked for).
- Existing tests that read `ART.themed` / `FACES.worlds` or set another theme call `loadAllArt()` first.
- `node tools/art_gate.mjs` stays green with `ui/art` and `docs/sprites` unchanged.
