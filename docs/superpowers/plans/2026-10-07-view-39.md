# Two Views (Flat 3/4 and 39°) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Date: 2026-10-07. Trial: branch `iso-trial`, `tools/iso.html` (`tools/iso.mjs`, `tools/faces.mjs`, `tools/iso_art.mjs`).

**Goal:** The hall can be shown in two views, switchable live in Settings: today's **Flat 3/4** and a **39° view**
(horizontal rotation 39°, back wall receding 3:1, side wall 2:1), for every theme, both drawn from one shared art
source. Every world also gets a tall window and full-height wall hangings (the Warhammer gothic window and banners
from the trial; each other world its own design in its own style).

**Architecture:**
- **Floor model is the truth.** Layout, routes, roster, seats, queue, lights stay in today's hall logical px (`x`, `y`).
  A view only projects. Mapping to the 3D world (art px): a floor point `(x, y ≥ WALL)` → `u = 2x, v = 2(y − WALL),
  z = 0`; a point on the back wall band `(x, y < WALL)` → `u = 2x, v = 0, z = 2(WALL − y)`.
- **39° projection** (exact, from the trial): `P39(u, v, z) = [u − w, ⌊u/3⌋ + ⌊w/2⌋ − z]` with `w = ⌊v·√(2/3)⌋`.
- **Static parts** (room shell, walls, floor, static props) are rendered once per size/theme/day by a CPU z-buffer
  (`ui/iso.js`, ported from the trial's `Buf`) into a char grid, painted to a cached canvas: zero per-frame cost.
- **Objects are face sheets** (`ui/faces.js`): front + details cut from today's frames (shared), side + top faces as new
  art (39° only), flat-only retouches. The flat frame recomposed from its faces is pixel-identical to today's.
  Each box prop's 39° frame is pre-rendered once (per theme) into a sprite canvas with its anchor (floor footprint).
- **Characters** are the only per-view drawn art: 39° families `scribe39`, `adept39` (and the magos/skull where needed),
  4 diagonal facings × 3 walk frames (+ a seated/working pose).
- **Dynamic layer** (desks placed by the layout, actors, fx, paper, labels) is drawn each frame by projecting floor
  positions and depth-sorting by floor footprint (the trial's `order`).

**Tech Stack:** vanilla ES modules, Canvas 2D, PNG sheets in the key palette (`ui/art/key.gpl`), node assert tests.

## Global Constraints

- Flat view stays exactly today's look **except** the deliberate wall changes of Task 3 (taller back wall, tall
  window, full hangings). Every other flat pixel unchanged.
- Only two views exist: `flat` and `39`. No other projection, no depth level setting (depth is always on).
- Setting `adm.view` = `flat` | `39`, default `flat`, applied live (caches dropped like a theme change); the remote
  view keeps its own (`LOCAL` in `settings.js`). Label: "View" with options "Flat" / "39°".
- One art source: no sprite exists twice. Shared = fronts, details, textures, small props, windows, hangings.
  39°-only = side faces, top faces, 39° characters. Flat-only = retouch layers.
- Art lives in `ui/art/` (base = Warhammer) and `ui/art/<world>/` (cyber, orbital, tower, vault), PNG + JSON in the key
  palette; a world's sheet holds only the frames it redraws. New worlds' art is a new design, never a recolour of 40k.
- No change to `src-tauri/` except if a task says so. No new dependency.
- Tests: `node ui/*.test.mjs` all green; new pure code has a plain-assert test. Look at art in the browser
  (`python -m http.server 8123`, `tools/sprites.html`, `tools/preview.html?view=39`).
- After an art change: `node ui/art.test.mjs`, `node ui/sprites.test.mjs`, regenerate galleries
  (`node tools/sprite_sheet.mjs`, `--theme <id>` for cyber, orbital, tower, vault).
- Commits: one per task (or a few), subject `View: <what>`; no attribution lines. LF line endings.

## Task 1: iso engine (`ui/iso.js`)
Write set: `ui/iso.js`, `ui/iso.test.mjs`.
- Port the trial's `Buf` (z-buffer: `px`, `put`, `box`, `decal`, `bill`, `outline`, hole fill, `rows`) as a pure module
  (no DOM): `export class IsoBuf { constructor(w, h, ox, oy) … }`, `export const P39`, `export const VS39 = 2 / Math.sqrt(2 / 3)`,
  `export const floorToWorld(x, y, WALL)`, `export const order(a, b)` (footprint depth sort from the trial).
- Only the 39° projection; drop the others and the trial-only options.
- Tests: P39 stairs are clean (u step: x +1, y +1 every 3; v step: 2-2 stairs), a box renders its 3 faces with
  correct hidden-surface removal, `order` puts a desk in front of a scribe standing north of it, `outline` marks edges.

## Task 2: face sheets (`ui/faces.js`) + base side/top art
Write set: `ui/faces.js`, `ui/faces.test.mjs`, `ui/art/faces.png`, `ui/art/faces.json`, `tools/sprite_catalog.mjs` (faces section).
- Data, not code: `ui/art/faces.json` lists per object (`DESK`, `LECTERN`, `CONSOLE`, `SHELF`, `COGITATOR`, `CRATE`,
  `TABLE`, `BENCH`, `RECAFF`, `LORD_DESK`, `THRONE`, and any other box prop) the front rect and details rects inside
  today's frame, flat-only rects, 3D size `w d h`, detail kinds (`box`/`top`/`bill`/`decal`/`drum`) with 3D anchors;
  side and top faces are frames in `ui/art/faces.png` (key palette). A world may override in `ui/art/<world>/faces.*`.
- `composeFlat(sheet)` rebuilds the flat frame; `sheetOf(name)` returns the active theme's sheet (like `sprites.js`).
- Test: for every object and every theme, `composeFlat` equals the theme's current `MAPS[name]` pixel for pixel.
- Draw the base (Warhammer) side/top faces as PNG frames (the trial's rules are a starting point: wood, iron, brass).
